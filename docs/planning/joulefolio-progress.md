# Joulefolio Progress

## Current Snapshot

As of `2026-06-18`

- 1차 MVP 기준 진행률: `약 75%`
- 전체 로드맵 기준 진행률: `약 40%`

### Scope Basis

- 1차 MVP는 현재 기획의 핵심 데모 범위인 대시보드 정적 및 목업 데이터, 거래 요청 플로우, 커뮤니티 피드 UI, 기본 상태 관리, 반응형 레이아웃을 기준으로 본다.
- 전체 로드맵은 1차 MVP에 더해 친구 목록, 거래 상태 고도화, mock API, 실시간 데이터, 거래 승인 플로우, 랭킹 및 배지, 지도 기반 커뮤니티, WebSocket 또는 SSE까지 포함한다.

### Evidence

- 구현 완료 또는 높은 진척:
- 랜딩, 대시보드, 거래, 커뮤니티의 주요 라우트가 모두 존재한다.
- 대시보드 차트, 요약 카드, 거래 카드, 커뮤니티 피드와 필터 등 핵심 UI가 구현돼 있다.
- 목 데이터, 엔티티 타입, 위젯 단위 테스트, 일부 E2E 테스트 기반이 갖춰져 있다.
- 국제화 구조와 기본 디자인 시스템이 포함돼 있다.

- 부분 구현:
- 거래 화면은 입력과 예상 금액 계산은 가능하지만, 상태 전이 중심의 플로우는 아직 단순하다.
- 서버 상태와 클라이언트 전역 상태는 설계와 의존성은 있으나, 본격적인 데이터 계층 사용은 아직 제한적이다.
- 최근 활동, 거래 내역, 커뮤니티 상호작용은 데모 성격이 강하다.

- 미구현 또는 후순위 범위:
- 로그인, 친구 목록, 거래 승인, 알림, 실시간 데이터 반영
- 도매상 연동 또는 API 계층
- 랭킹 및 배지 고도화, 지도 기반 커뮤니티, WebSocket 또는 SSE

### Interpretation

- `75%`는 현재 프로젝트가 서비스 데모를 보여줄 수 있는 MVP에 가깝다는 뜻이다.
- `40%`는 기획안 전체에 적힌 제품 비전과 확장 범위까지 포함하면 아직 절반 이하라는 뜻이다.
- 이 수치는 정량 측정값이 아니라 현재 저장소 기준의 구현 범위 평가치이며, 기능 우선순위가 바뀌면 함께 조정한다.

## Next Priorities

1. 거래 화면 상태 설계 고도화
   현재 `TradeForm`은 기본 입력과 예상 금액 계산 중심이다. 다음 단계에서는 `idle`, `editing`, `validating`, `pending`, `success`, `failed` 흐름과 유효성 검사를 반영해 거래 UX를 실제 데모 수준으로 끌어올린다.

2. 거래 도메인 및 목데이터 정리
   거래 대상 목록, 상태별 거래 내역, 요청 결과를 `src/entities/trade`와 `src/shared/mock` 중심으로 정리해 화면과 데이터 모델이 같은 구조를 보게 만든다.

3. 대시보드와 거래 화면 데이터 연결
   대시보드의 거래 가능 에너지와 거래 화면의 판매 가능 전력이 같은 출처를 보도록 연결해 화면 간 흐름을 강화한다.

4. 커뮤니티 상호작용 확장
   필터 중심 피드에서 한 단계 더 나아가 거래 후기, 활동 맥락, 상호작용 경험을 강화해 플랫폼 느낌을 높인다.
